# 本地对话式课程规划助手

本仓库包含对话式课程规划助手的完整源码。启动本地应用后，在“AI 规划助手”标签中使用；GitHub Pages 仍为静态演示，不运行对话模型或求解服务。

## 验收流程

1. 输入“我想学游戏开发，有哪些相关课程？”，查看 `search_courses` 的真实调用记录、向量/关键词状态、课程卡片及先修条件。
2. 接着输入“帮我生成阶段规划，累计目标72 CP，每学期最多18 CP”，检查待确认条件。此时尚未运行求解器。
3. 输入“其他要求不变，每学期上限改成12 CP”，确认新条件保留兴趣和累计目标；旧按钮不可再使用。
4. 点击“确认条件并生成方案”。求解由 OR-Tools 执行，结果通过独立 audit 后才显示。无解时展示求解器返回的信息，可以继续对话调整条件。
5. 点击“在路径方案中查看”，查看同一份结果、确认过的参数、比较卡片及学期明细。修改表单条件会清空旧结果，需重新生成。
6. 如需使用结果，在路径面板点击“采用并新建计划”；保留原计划。仅对话、检索、确认求解都不会修改现有安排。

## 实现

- 模型：沿用本地 Ollama 的 `qwen3:1.7b`，通过原生 `/api/chat` tool calling 选择工具，没有引入 LangChain。
- `get_context`：读取当前 Program、已修、认可学分、安排及规划目标。
- `search_courses`：沿用 EmbeddingGemma + 本地向量索引 + 余弦检索；向量不可用时明确显示关键词回退。
- `check_courses`：调用确定性先修规则计算，返回真实课程卡片与官方历史来源。
- `prepare_pathway`：整理可编辑的阶段规划条件，服务端验证课程白名单、参数范围及冲突；用户确认前不求解。
- `solve_pathway`：用户点击确认后执行已保存的条件，调用 `lib/pathway-service.ts`，与独立路径面板共用服务，不允许模型绕过确认。模型不负责计算学分或判断毕业资格。
- `lib/agent-contract.ts` 保存前后端类型、上下文标识及条件验证，`lib/course-agent.ts` 实现有界工具循环，`app/api/agent/route.ts` 提供同源本地接口。
- 结果传递给原 `PathwayPanel`，不在另一个面板重复计算或制作不同版本的求解结果。

## 状态和边界

- 每轮最多4次工具调用，每次对话最多12轮，30分钟不活动后过期；会话只保存在本地服务内存，不写入账号库，刷新页面后不恢复。
- 切换计划、专业、推荐学期或改变学术档案后开始新对话，旧结果不能继续采用。模型不获得邮箱、学号或真实姓名。
- 模型不能执行命令、访问任意地址、修改认可学分、已修课程或直接保存计划；阶段目标的累计CP包含已完成与认可学分。
- 小模型可能误解复杂自然语言，必须核对确认卡片；条件不清楚时可追问或使用独立表单。保留原单次检索入口。
- 资料为2024历史快照，只有已录入约束能自动验证，生成的是阶段候选方案，不等于校方批准的毕业路线。
- GitHub Pages 不提供 Agent、Ollama 或 Python 服务；源码随仓库发布，完整功能需要本地服务。

## 验证

Node 参数与上下文测试、现有课程规划测试、Python 求解/audit测试，以及真实 Ollama 多轮检索—修改条件—确认—求解联调；另在本地浏览器检查结果移交和参数变更失效行为。
